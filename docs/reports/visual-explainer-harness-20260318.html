OpenCode: Best Pass Rate (22%)

Highest pass rate with 88% fix rate. Connected to vLLM via custom @ai-sdk/openai-compatible provider. Required 64K context due to ~11K system prompt + ~20 built-in tool definitions.

Claude Code: Best Precision (53%)

20% pass rate with only 38% fix rate — but 53% of its fixes pass (10/19), double OpenCode's 25%. Required patching 3 bugs in vLLM's Anthropic Messages API (/v1/messages): tool_use_id parsing, streaming argument drop, and Mistral ID format. Needs 131K context (TP2) due to 32K max_tokens + ~22K system prompt.

Codex CLI: Highest Fix Rate (96%), Lowest Precision (19%)

96% fix rate (48/50) but only 18% pass rate (9/50). Edits via shell commands (cat >, sed, heredocs) rather than structured edit tools. Stateless Responses API resends full conversation each turn, consuming ~1.4M tokens/issue (140x more than OpenCode). Adds 2 unique passes (django-11630, django-12747). Required a streaming-to-non-streaming proxy + 4 vLLM patches.

Hashline: Same Rate, Different Issues

The LINE:HASH format that gave Grok a 10x improvement (6.7% → 68.3%) provides no advantage for Devstral Small 2 24B. But it uniquely solves sympy-18835.

19x Token Overhead

Hashline averages 191K tokens/issue vs ~10K for str_replace. The LINE:HASH prefix on every line inflates context by ~19x. For weak models, the bottleneck is fix correctness, not edit addressing.

Phase 3 Implication

42% of failures are "wrong fix" — the model understands the problem area but applies incorrect logic. This is a trainable error pattern. A LoRA finetuned on successful fix trajectories (especially the 4 both-pass issues) could target this class.

Key Insights

Parkinson's Law for Agents

The model fills available time with exploration. First edit occurs at 58-65% of the turn budget regardless of size. 10 turns or 30 turns — same proportional delay.

Context Compaction Actively Hurts

Config F (compact at turn 15) achieves 40% fix rate — the worst. Stripping context causes re-reads and loops. 41.3% repeat rate is highest across all configs. Don't compact; give more turns instead.

Ensemble Is the Biggest Single Win

Running all 7 harnesses lifts pass rate from 14-22% to 32%. Larger than any turn strategy, prompt, or tool optimization.

Precision vs Recall: Claude Code vs OpenCode

OpenCode: 88% fix rate, 25% precision. Claude Code: 38% fix rate, 53% precision. Claude Code's massive system prompt (~22K tokens) makes the model conservative — fewer but better fixes. Harness design affects quality distribution, not just quantity.

Hashline Helps Strong Models, Not Weak Ones

The LINE:HASH edit format that gave Grok 10x gains provides no advantage for Devstral Small 2 (14% vs 14-16%). Uses 19x more tokens. But uniquely solves sympy-18835.

Shell-Based Editing Solves Different Issues

Codex CLI's shell commands (cat >, sed, heredocs) solve 2 issues no structured edit tool handles (django-11630, django-12747). Highest fix rate (96%) at the cost of 140x token consumption (~1.4M tokens/issue).

CLI Agents Push the Frontier to 18-22%

OpenCode (22%), Claude Code (20%), and Codex CLI (18%) all use built-in tool sets rather than custom adapters. The structured system prompts of production CLI agents extract more capability than bespoke harnesses (14-16%). Ensemble ceiling of 32% suggests finetuning is the next lever.

Conclusions

  1. 30 turns baseline is optimal — compaction and restart strategies hurt or are neutral.
  2. 7-harness ensemble reaches 32% (16/50) vs 14-22% individual. Each new harness adds 1-2 passes.
  3. OpenCode best pass rate (22%), Claude Code best precision (53%) — CLI agents beat custom adapters.
  4. Codex CLI: highest fix rate (96%), lowest precision (19%) — shell-based edits solve different issues.
  5. Fix rate ≠ pass rate — conversion ranges from 19% (Codex) to 53% (Claude Code) depending on harness design.
  6. Hashline helps strong models, not weak ones — same rate but unique issues (ensemble value).
  7. Phase 3 (finetuning) is now relevant — 42% wrong-fix failures are trainable.
  8. Full evaluation requires Docker — bare-metal eval covers ~50% of patches.
