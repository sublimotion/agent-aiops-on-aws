Methodology Companion

This tab maps the presentation concepts into the selector: why per-token cost is incomplete, why routing matters, and how to interpret the evidence labels.

1. The tokenmaxing wall

Coding agents consume tokens at agent-fleet rate, not headcount rate. One engineer can run foreground, review, debug, overnight, and continuous agents at the same time.

The practical failure mode is not only price. It is quota resets, 429s, degraded modes, context loss, and stalled autonomous work.

daily_tokens ~= engineers * agents_per_engineer * tokens_per_agent_day

2. The buying metric is shipped work

The selector uses estimated cost per solved task because engineering managers buy resolved PRs, not raw output tokens.

A cheap model that fails often can be more expensive than a stronger model after retries, review time, and escalation are counted.

value = shipped_tasks * value_per_task - (model_cost + harness_cost + infra_cost)

3. Why routing beats one-model thinking

Not every task requires frontier capability. The selector treats the model stack as a router: cheap endpoints handle routine work, stronger open-weight models handle hard local work, and frontier APIs recover the tail.

  • T0: lint, formatting, docs, small mechanical edits.
  • T1: localized bug fixes and focused test repair.
  • T2: multi-file changes, repo navigation, tool-heavy work.
  • T3: ambiguous design/debugging and hard SWE-style tasks.
  • T4: fallback to frontier API when local confidence is low.

4. Default capability floors

The task tier auto-selects a starting capability floor. These are routing thresholds, not universal benchmark truths; they should be recalibrated with your own accepted PRs and CI outcomes.

TierFloorRationale
T0 small edits50Mechanical changes can use cheap coder endpoints with fast escalation.
T1 localized bug60Admits Devstral-class endpoints that showed strong BFCL and simple functional task results.
T2 multi-file70Requires stronger repo navigation, context handling, and tool-loop reliability.
T3 hard repo issue78Near-frontier open models or strong official SWE-bench class results.
T4 fallback82Reserved for frontier API or the strongest measured local workhorse.

5. How solved-task cost is estimated

The current draft separates local task cost, expected model success, and fallback cost. This is intentionally approximate until every model has a matched fix-rate and serving-knee run.

local_task_cost = output_tokens * output_cost + input_tokens * input_cost_factor * (1 - cache_discount) solved_task_cost = local_task_cost / expected_success + fallback_rate * frontier_task_cost

6. Endpoint utilization changes the economics

A B200 or B300 node is a fixed asset once reserved. The cost curve improves when many agents share the endpoint and push it toward its measured throughput knee.

This is why the fleet tab focuses on traffic mix and utilization before exact pod packing.

node_cost_per_task = node_cost_per_hour / solved_tasks_per_hour_at_knee

7. Prompt cache and context strategy matter

Agent traffic often repeats repo instructions, system prompts, coding standards, and stable codebase context. Prefix cache hit rate can materially change TTFT and effective cost.

High reuse favors replicas and cache-aware routing. Low reuse with long fresh context can require prefill/decode separation or a different endpoint shape.

8. Evidence labels are part of the result

The selector does not treat all benchmark numbers as equally strong. Vendor-reported capability, our measured serving, and same-harness fix-rate are separate evidence axes.

  • High: same-harness task outcome plus measured serving cost.
  • Medium: one strong axis measured, the other vendor-reported or proxy-based.
  • Low: partial traces, harness issues, or missing serving-knee data.

9. Owning the endpoint starts the flywheel

The endpoint is not only a cheaper token source. It is where traces, PR diffs, review accepts, test pass/fail, and CI signals can compound into a domain-tuned coder.

open coder -> trace capture -> reward signals -> distillation/fine-tune -> better local coder
