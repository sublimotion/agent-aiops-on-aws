Key Insights

vLLM Wins on Throughput: +17% Peak, +41% at Single-Stream

vLLM consistently outperforms SGLang across all concurrency levels. At conc=1, vLLM delivers 76.5 tok/s vs SGLang's 54.1 tok/s (+41%). At peak concurrency=256, vLLM reaches 1,449 tok/s vs SGLang's 1,238 tok/s (+17%). The gap narrows at higher concurrency as both systems become compute-bound.

vLLM Wins on TTFT: 2-4x Lower Latency

vLLM's TTFT advantage is dramatic. At conc=64: vLLM 974ms vs SGLang 4,146ms (4.3x). At conc=128: vLLM 6.2s vs SGLang 7.7s (1.2x). vLLM's Dynamo image with TRITON_ATTN backend handles the Mamba-2 hybrid attention more efficiently for prefill.

Head-of-Line Blocking in Both Engines

TTFT p90 explodes in both: vLLM goes from 337ms (conc=1) to 44.5s (conc=256); SGLang from 492ms to 48.7s. Both engines suffer from aggregated prefill/decode sharing the same GPUs. Disaggregated prefill/decode would isolate these workloads on dedicated GPUs.

Disaggregated Mode BLOCKED for Mamba Hybrids

SGLang disaggregated prefill/decode with NIXL transfer crashes on Nemotron-3-Super. The Mamba-2 recurrent state + attention KV hybrid cache is incompatible with NIXL's transfer protocol. SGLang issues #19158, #18414, #19045 track this. PR #19254 (hybrid PP+PD support) is in progress but not merged. vLLM disaggregated mode is also unsupported (Dynamo PR #7216).

Mamba-2: Efficient Decode in Both Engines

ITL stays remarkably close between engines: vLLM 6.6ms vs SGLang 10.5ms at conc=1; vLLM 44.7ms vs SGLang 36.0ms at conc=256. The Mamba-2 recurrent state enables O(1) per-token decode without attention KV cache growth. At high concurrency, SGLang's ITL is actually slightly better.
