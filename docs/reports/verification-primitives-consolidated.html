Key Insights

Two-stage checkpoint solves Parkinson's Law
Edit@40% + Verify@55% shifts first tool use from 67% → 54% of budget. full_pipeline becomes the dominant pattern. Fix rate: 95% (+30pp). Gold pass: 24% (+10pp, p=0.0009).
CLAUDE.md guidance matches checkpoint injection
83.7% tool adoption in Claude Code headless with CLAUDE.md workflow instructions — matching the 83% achieved by system-level checkpoint injection. full_pipeline usage rises from 45% to 70%.
Tool users pass at 3.7x the rate of non-users
69.5% vs 18.8% gold pass (Fisher p=0.0001, OR=9.86). The adversarial review step is the key differentiator: full_pipeline (gen→run→review) produces 69.2% gold pass.
Agents never discover TDD independently
Without checkpoint injection, 0% tool adoption. Parkinson's Law dominates. Two-stage design engineers early verification without mandating it.
Stronger models compose more richly
Sonnet adopts tools 3.2x more than Haiku, uses 4 distinct patterns (vs 3), discovers full_pipeline_iterate. Verification primitives amplify model capability.
$0.01/issue verification overhead
852 Haiku calls for 300 issues = $3.20 total. Negligible vs generation cost (~$1/issue). ROI: +10pp gold pass for +1.6% cost.

Research Question

Core Hypothesis

Agents given verification primitives as callable tools will discover effective verification patterns (front-loaded testing, adversarial review before submission) that improve pass rate, without human-engineered orchestration.

Motivation

CoderForge's 413K-trajectory analysis found that early test fraction is the single strongest predictor of agent success. But those agents only had access to existing repo tests. What happens when you give agents the ability to generate their own verification?

Verification Primitives (3 Tools)

generate_tests

LLM-generated test suites via Bedrock Haiku
Input: problem statement + current patch diff + source files
Output: pytest test file content
Modes: confirmatory vs adversarial (inner prompt)
Cost: ~$0.008/call

run_tests

Sandboxed pytest execution in workspace
Input: test file content + workspace
Output: per-test pass/fail, stdout, stderr
Timeout: 60s per suite
Cost: compute only

adversarial_review

v009 adversarial rubric, single LLM call
Input: problem statement + patch diff
Output: structured verdict + score 0-1
Rubric: 5-axis (problem alignment, logic, completeness, scope, test safety)
Cost: ~$0.005/call

Experimental Design

Benchmark

SWE-bench Lite — 300 real GitHub issues across 12 Python repos. Phase 1-4 used a 50-issue stratified subset. Phases 5-6 used the full 300. Production eval used all 300 with Docker evaluation.

Agent Setup

  • Models: Haiku 4.5 (Phase 1-3), Sonnet 4.6 (Phase 4-6, production)
  • Turn budget: 30 turns
  • Standard tools: read_file, edit_file, list_dir, search, bash
  • Original harness: Custom Python harness with system-level checkpoint injection
  • Production harness: Claude Code headless (claude -p) with CLAUDE.md workflow guidance

Two-Stage Checkpoint Design

Edit nudge at 40% (turn 12): "You've explored enough — make your edit now."

Verify nudge at 55% (turn 17): "Run generate_tests and run_tests on your patch, then adversarial_review."

This separates the "stop exploring" signal from the "start verifying" signal, directly targeting Parkinson's Law.

Evaluation

  • Original experiment: Local gold eval (gold test_patch applied, pytest run in venv). Lower bound — no Docker.
  • Production eval: Official SWE-bench Docker evaluation. --namespace swebench for pre-built images. 8 parallel workers.
  • Statistical testing: Fisher's exact test (two-sided) on 2x2 tables. Significance: p < 0.05.

Limitations

Single model family
Only Claude models tested (Haiku 4.5, Sonnet 4.6). Results may not transfer to GPT-4, Qwen, or open-source models. The v009 rubric is Claude-calibrated.
Checkpoint injection confound
The checkpoint reminder may improve fix rate by reducing abandonment, independent of verification tools. The two-stage design partially addresses this.
No multiple-comparison correction
Each phase tests one primary hypothesis, but many variants were tested overall. Phase 4 p=0.028 would not survive Bonferroni.
Production eval has no control cell
SWE-bench production eval only ran the treatment (VP + CLAUDE.md), not a matched control. The 58.3% pass rate is compared to published baselines, not a paired experiment.
