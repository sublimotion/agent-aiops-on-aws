Trinity Coordinator

An evolved (CMA-ES) LLM router over a Bedrock model pool — reproduction, what broke, and the pivot to a cost-aware experiment.

arXiv 2512.04695 Bedrock Converse CMA-ES (gradient-free) domains/autoresearch

1 · The one-sentence idea

A tiny coordinator (Qwen3-0.6B + a ~19K-parameter head) reads the hidden state of a conversation and decides, each turn, which model from a pool should act and in which role (Solver / Thinker / Verifier). It is trained not with reinforcement learning but with evolution (CMA-ES) over its tiny parameter vector.

Why this matters here: our own prior GRPO router experiment was a negative result — a single-policy RL router collapsed below best-static on a multi-modal cost-aware reward. Trinity is the gradient-free alternative our write-up named. The paper's own bake-off agrees: sep-CMA-ES 0.615 > SFT 0.592 > RS 0.374 > REINFORCE 0.253 — REINFORCE (≈ our GRPO) is dead last.

3 · The three-role scaffold (multi-turn)

Solver
role 0 · produces an answer
⇄
Thinker
role 1 · suggests next step + role
⇄
Verifier
role 2 · ACCEPT / REJECT

Each episode runs up to 5 turns. A Verifier ACCEPT halts early. The head picks (model, role) each turn from the conversation state. This scaffold is the second thing Trinity bundles — and the experiment must separate its effect from the routing effect (see §6).

5 · The pivot — make COST the optimized axis

When accuracy is at the ceiling, raw pass-rate has no headroom — but cost does. The question becomes: "hit 0.93 as cheaply as possible." Reward is reshaped as a budget-constrained Pareto objective:

reward = raw_passrate − λ · max(0, episode_cost − budget)
cost is measured, not guessed

A provider-agnostic token counter reads Bedrock Converse usage.{inputTokens,outputTokens} — identical schema across Anthropic / Amazon / Qwen / DeepSeek / Gemma. Pricing is applied separately so counts stay reconcilable if prices change.

sweep λ → Pareto frontier

λ ∈ {0,1,10,100}. λ=0 = accuracy-only baseline (frontier-heavy). Higher λ pushes routing toward cheap-but-adequate. The frontier is the result.

free role binding

The head may assign any model to any role. We observe whether evolution discovers the economically-rational stratification: cheap Solver, frontier model reserved for the high-leverage Verifier turn.

Validated end-to-end. Pre-check iter 0: shaped = 1.0 − 100·(0.0103 − 0.0005) = 0.0182 — the reward math is exact and the per-episode cost is real measured tokens.

6 · The viability gate — does routing even help?

Routing only earns its keep if the pool has a genuine cost/capability trade-off. If every model passes the same problems (low capability variance), routing is pointless no matter the price spread. We measure this before training, with a per-model solo pass matrix.

Why this answers "what if we saturate on a cheap flagship too?" — the pass matrix measures capability variance directly instead of assuming it. Either outcome is a publishable result; the row-1 case ("you don't need Opus at all here") is arguably the most provocative for the cost-aware-routing thesis.

The thesis is confirmed — and stronger than "don't need Opus." The single best model is open: deepseek-v3 at 0.87 beats Opus's 0.73 at 1/5th the cost. Four open flagships (deepseek-v3, qwen3-235b, qwen3-coder-480b, gpt-oss-120b) match or beat Opus at 1/5th–1/16th the price; Opus sits mid-pack at 10–50× the cost of equally-capable open models. On this task class, paying for Opus buys nothing.
Routing still has headroom (not saturated). A perfect router (oracle = solve-if-any-model-solves) reaches 0.967 vs the best single model's 0.867 — +10 points. And a cheap-first policy already wins: gpt-oss-120b + escalate-to-Opus-on-failure = 0.867, beating Opus-only (0.73) while spending a fraction. The router's job here is less "reach higher accuracy" and more "reach deepseek-v3-level accuracy for deepseek-v3-level cost, with frontier escalation only for the residual hard tail."

7 · What "transferable / generalizable" means

Transfers freely

  • Across tasks, fixed pool. The head reads a semantic hidden-state embedding, not model IDs — a head trained on LiveCodeBench transfers to MATH/MMLU without retraining.
  • The cost-aware policy ("escalate to expensive only when the embedding signals hard") is itself a model-agnostic strategy that should carry over.

Does not transfer freely

  • Changing the pool. The positional head bakes pool composition into its output geometry.
  • Swap a model at an ord → logits transfer, economics mis-calibrated.
  • Add a model → widen the output layer, warm-start the known neurons, run a short top-up evolution.
Research extension — a content-addressed head. Condition each model's logit on a descriptor ($/Mtok, capability embedding, context window, reasoning?) instead of a bare position. Then adding a model = appending a descriptor row — no architecture change — and one trained coordinator can route any pool by reading model cards. Price lives in the descriptor, so it fits the cost-aware framing directly. A materially stronger "generalizable" claim than the paper's.

8 · Why CMA-ES, not RL

The trainable vector is tiny (~19K params) and the reward is multi-modal and non-differentiable (cost penalties, discrete routing, early-halts). Single-policy gradient RL collapsed below best-static on exactly this shape (our GRPO negative result). Evolution strategies — population-based, gradient-free — handle rugged reward landscapes without a value function or policy-gradient variance. The paper's bake-off and our own result both rank REINFORCE last.

9 · Hard-won engineering lessons (selected)

the vendored code is eval-only
The training loop, _calculate_closed_source_costs, and every *_bonus_weight knob were missing or dead. All reward shaping had to be built, not configured.
spawn-Pool isolation
Monkeypatches, cost, and token counters live per-worker-interpreter. Bridged via sitecustomize.py + per-PID telemetry sink files the main process aggregates.
reasoning-token clip
Bedrock clips the first answer token at the reasoning→text boundary (qwen reasoning) — silently flipping Verifier ACCEPT→REJECT. Caught by the 21-cell role-audit gate, repaired in extraction.
executor hang
Grading generated code with using_closed_models=True skips the signal alarm → an infinite-loop solution hangs forever. Arm the alarm.
resume safety
CMA-ES state pickled + S3-synced every iter; iter-0 durability is a hard gate. A reclaim costs one iter, not the run.
degeneracy gates
Worker non-degeneracy, role usage, entropy > 1.5, and a brand-concentration < 40% check (the rl-conductor 52%-Opus-skew failure mode).
