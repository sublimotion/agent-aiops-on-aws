Disaggregation: The Most Overapplied Optimization
4 scenarios where disagg is actively harmful
Our field data shows disagg hurts in the majority of single-node deployments
ANTI-PATTERN 1: Disagg + Prefix Caching
Prefix caching already eliminates 60-90% of prefill. Adding disagg introduces KV transfer latency for work that doesn't exist.
Without cache: prefill 5,928ms → disagg helps
With cache: prefill 57ms → disagg adds cost for 0 gain
ANTI-PATTERN 2: Disagg + Single-Node TP>1
TP8 already uses NVLink for AllReduce. KV transfer competes for the same fabric. Result: worse than no disagg.
K2.6 TP8 no-disagg: 10,437 tok/s
No disagg config matched this on same HW
ANTI-PATTERN 3: Disagg for Agentic (Short Turns)
Agentic turns have 1-4K input (mostly cached). Prefill is either free or takes <50ms. Disagg adds fixed overhead on every request.
ANTI-PATTERN 4: Disagg Without InfiniBand
On EFA, KV transfer requires CPU bounce (GPU→CPU→EFA→CPU→GPU). Adds 6-12ms per request. Wipes out any scheduling benefit.

When Disagg IS the Right Call

Multi-node (model doesn't fit one node) | Prefill-heavy workloads (RAG with 32K+ docs, first-turn only) | Mixed-priority traffic (batch + interactive sharing fleet) | InfiniBand + TP=1 (zero-contention cuda_ipc)

The B200 = B300 Secret

B200 and B300 have identical HBM bandwidth (8 TB/s/GPU). Since LLM decode is bandwidth-bound, they have nearly identical throughput. B300's only advantage is more VRAM (275 vs 141 GB). For agentic workloads with 32K effective context: B200 gives the same performance at 26% less cost.

Self-Hosted Break-Even

B200 + EAGLE3 monthly cost: ~$8,760. Claude Opus API: $2.25/task. Break-even at 3,893 tasks/month = 16 coding agents. Above 16 active agents: self-hosted dominates. The value isn't cheaper tokens — it's unlimited tasks within fixed budget.

Quick Reference: What to Do First
DO (in this order)
  1. Enable CUDA graphs (default in vLLM/SGLang)
  2. Verify MoE tile config exists for your GPU
  3. Enable prefix caching (--enable-prefix-caching)
  4. Add EAGLE3 if draft model available
  5. Test dynamic MLA routing for short prefills
  6. Right-size: B200 unless you need >100 sessions @ 128K
  7. Measure with standard workload catalog
DON'T
  1. Add disagg before trying prefix caching
  2. Use EP on single-node (dispatch overhead > GEMM gains)
  3. Benchmark with --enforce-eager (5-15x worse than prod)
  4. Assume bigger instance = more throughput (BW matters, not VRAM)
  5. Optimize kernels before measuring system overhead
  6. Go multi-node before exhausting single-node optimizations
  7. Choose model by $/token (choose by $/successful-task)
