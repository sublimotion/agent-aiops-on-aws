### Cross-cutting patterns identified

#### Pattern 1: Verification asymmetry as a meta-principle (spans verification AND authoring)
**Occurrences:**
- E_fin1: adversarial skill-verifier lift 2.3× (coding) → 0.99× (FinQA) — verification requires checking-cheaper-than-generating
- E_harness2: external harness-authoring lift predicted (from T5) → NULL (−0.025/−0.008) — authoring locus inert without an asymmetry

**The generalized law:** External-vs-self locus is inert for ANY agent-construction engine (verifier, harness author, critic) UNLESS the external party has a cheaper/more-reliable check than re-deriving the answer. Both verification and authoring obey the same rule: asymmetry is the active ingredient, not "external" or "adversarial" framing alone.

**Abstraction level:** This is a **meta-principle for autoresearch experiment design** — it predicts when external>self will pay off across verification, authoring, critique, reward modeling. It transcends both specific domains (coding vs FinQA vs SQL) and specific primitives (verification vs authoring).

**Elevation target:** `.claude/steering/product.md` has no autoresearch methodology section. This belongs in a **new steering file** for autoresearch/agent-design methodology, or in a new section of `product.md`. Forcing it into `tech-stack.md` (AWS/serving-focused) or `benchmark-analysis.md` (serving benchmarks) would be a category error.

#### Pattern 2: Per-failure-class replication gates (pooled accuracy false-negatives on strong backbones)
**Occurrences:**
- E_harness2: pooled L0→L1 +5.0pp (below +12–16pp gate) BUT SELECT-class +64pp (faithful reproduction)
- E_fin1 (implicit): label noise / scoring artifacts can hide a true differential lift (11/29 "wrong" answers were scoring artifacts)

**The rule:** When replicating an intervention on a different backbone, verify per-failure-class before calling it failed. Pooled accuracy can false-negative on a stronger model if the intervention targets a failure class that is now a thin slice. Always break down by the failure class the intervention TARGETS and audit ≥5 fix-trajectories.

**Abstraction level:** Autoresearch/eval methodology — applies to any replication attempt, not specific to SQL or harness engineering.

**Elevation target:** Same as Pattern 1 — autoresearch methodology.

#### Pattern 3: Native Bedrock tool-use multi-tool-turn requirement (operational)
**Occurrences:**
- E_harness2: multi-tool turn crash (`ValidationException` on missing toolResult for second toolUseId)
- agent-harness (context from lessons.md): SDK-on-non-native-backend has tool-call edge cases

**The rule:** Native `aws bedrock-runtime converse` tool-use requires a `toolResult` for EVERY `toolUseId` in the assistant turn, even if only the first is acted on. Multi-tool turns crash without filler toolResults for the rest. OpenAI Agents SDK would mask this.

**Abstraction level:** Bedrock API operational detail — applies to any native-Bedrock agent loop, not specific to harness authoring.

**Elevation target:** `.claude/steering/tech-stack.md` → AgentCore Conventions or a new "Bedrock API Conventions" section (this is API-level, not AgentCore-specific).
