Headline goal

Don't always use Opus 4.7. Train a router that picks the cheapest capable worker per question.

3. Reward function

reward = is_correct ? max(0.01, exp(−α · cost_norm_log)) : 0 + 0.05 format-validity bonus. Bounded in [0.01, 1.05] when correct; zero on wrong answer (with format bonus retained as +0.05). Log-cost normalization gives every OOM equal weight, so workers in the $0.001–$0.01 band produce real gradients.

Worker (sorted by cost) $/q cost_norm_log α=0.1 α=0.3 α=1.0 α=3.0 α=5.0
What the experiment teaches the router: at α=3, picking Haiku correctly is worth 0.24 reward; picking Opus correctly is worth 0.05. The router learns to avoid Opus unless the question genuinely demands it. This is the experiment.

4. Phase 0 — pre-flight gates (BLOCKING)

Each gate is a script that exits non-zero on failure. No training run launches until all green. Every gate cites the rl-conductor failure it prevents.

GATE 0.1
Setup audit (apply_chat_template)
Prevents: ~10 days lost on rl-conductor to "ordinal bias" symptom-chasing — root cause was tokenizer(raw_text) instead of apply_chat_template on a chat-tuned Qwen.
GATE 0.2
Reward unit tests
Prevents: 4 silent reward bugs (HumanEval string-match, MCQ regex, MATH normalization, wrong answer extraction) — worth ~25-40pp plateau, unrecoverable without retraining.
GATE 0.2b
Per-worker output-format audit
Prevents: new workers (Kimi K2 Thinking, Opus extended, GLM 5, MiniMax M2.5, DeepSeek) emit <thinking> blocks that break naive extractors silently. Audit matrix per (worker, dataset) cell.
GATE 0.3
Judge calibration
Prevents: mis-calibrated Haiku-as-judge silently mislabeling rewards. Requires Haiku↔human ≥90% on 30 hand-graded math items; escalate to Sonnet judge if <90%.
GATE 0.4
Brand-bias diagnostic at iter-0
Prevents: Qwen2.5-7B picks Opus 52% at iter-0 (project_qwen25_brand_bias.md). Mitigated here by Qwen3-8B + neutral codes; Gate 0.4 verifies entropy ≥1.8 nats before launch.
GATE 0.5
Raw artifact capture
Prevents: per feedback_log_raw_artifacts.md, aggregate-only logging meant rl-conductor reward bugs were unrecoverable post-hoc. Full per-rollout JSONL → S3 (~5GB total, negligible).
GATE 0.6
Synthetic output sanity
Prevents: aggregate metrics looking fine while output is degenerate (synthetic-random spec-decode case). Manual visual inspection of 20 rollouts before each training launch.
GATE 0.7
Resume protocol locked
Prevents: cross-region GRPO resume catastrophically broke a 70% MATH500 run (format_fail 0%→27%). RNG state + LR÷10 warmup + KL β>0 warmup + same-AZ constraint.

5. Base model decision

Drop-in upgrade from rl-conductor's Qwen2.5-7B. Same family, same chat template, same training stack — newer corpus, expected lower brand bias.

Qwen2.5-7B-Instruct (rl-conductor)

  • Paper-faithful — Sakana Conductor used this
  • Documented 52% Opus skew at iter-0 (brand bias)
  • ChatML template, 8 GPUs ample at bf16
  • Older training corpus (mid-2024)

Qwen3-8B-Instruct (this spec)

  • Same ChatML family — Gate 0.1 logic carries over verbatim
  • Newer corpus (March 2026) → expected lower brand bias
  • Better instruction-following + structured-output adherence
  • Same parameter class, same GPU footprint
  • Honest improvement: we are building on the paper, not reproducing

6. Worker anonymization — mask_style='neutral_codes'

The router sees worker_alpha not "Opus 4.7". Provider names redacted from capability strings too. Code→ord mapping shuffled per training run (seeded).

Why this matters: Qwen2.5-7B's 52% Opus-skew prior comes from pretraining on Anthropic-flavored data — "Opus" is statistically the most-mentioned strong model in the corpus. With worker_alpha the router has no surface area to brand-pattern-match. Capability strings carry the actual routing signal (cost, specialty, ctx, weakness) — provider name has no causal role in "is this worker right for this question." Trade-off: lose any "Anthropic Haiku is fast" pretraining transfer; net positive because brand prior would actively interfere with cost-aware learning.

8. α sweep — five operating points

Each α is a separate training run that materializes a different "exchange rate" between cost and quality. The Pareto frontier is the union of all five.

Quality-dominant
Opus-heavy. Cost barely matters.
α=0.3
Quality-biased

α=1.0
Balanced
Trades 1% quality for 1% cost reduction. Most likely production sweet spot.

Cost-biased

α=5.0
Cost-dominant

9. Headline exit criterion — quality/$ ≥ 5× Always-Opus

Sketch of expected Pareto curve: the router family (red dots) should beat the convex hull of always-X baselines (gray dots) in hypervolume gain over a $0.30 × quality=0 reference point.
