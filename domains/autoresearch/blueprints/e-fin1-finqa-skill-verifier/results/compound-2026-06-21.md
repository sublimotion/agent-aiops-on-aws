### Experiment context
This is an autoresearch replication experiment testing whether the coding-domain adversarial skill-verifier lift (precision 0.40→0.92, 2.3×) transfers to FinQA financial numeric QA. **Result: NULL** — 0.99× lift (vs 2.3× coding). Both confirmatory and adversarial verifiers sit at the agent's base rate (0.71-0.74 precision); neither discriminates correct from incorrect answers.

The headline finding is **applicability-bounding**: adversarial verification requires a *verification asymmetry* (checking is cheaper/more reliable than generating, e.g. via test/execution oracle). Coding has this via test execution. Outcome-only numeric QA at a fixed model tier lacks it — same-tier verifier makes the same mistakes as the same-tier agent, so adversarial recomputation rubber-stamps errors (19/29 wrong answers got 4/4 "likely_correct").

**Cross-verifier confirmation**: The null reproduced on Amazon Nova-Pro (n=40 subset: Nova 0.92× lift, identical to Haiku's 0.92×). Both verifiers fail with the same "engaged-but-wrong" signature (confidently affirm wrong answers), NOT by abstaining. This confirms the FinQA null is a **domain/asymmetry property**, not a verifier-model-choice confound.
