## Observations for future autoresearch blueprints

1. **Phase 3 (finetuning) deferral justified**: 82% fix generation rate with 16-22% pass rate confirms scaffolding problem, not weights problem. Revisit finetuning only after harness optimization plateaus.

2. **Complementarity pattern**: SERA (turn pressure) and LangGraph (structured tool calling) produce different fix patterns that succeed on different issues. This suggests multiple orthogonal optimization axes exist in agent scaffolding design.

3. **Compaction is a double-edged sword**: Compaction prevents 400 errors from exceeding context limits but causes orientation loss and repeat loops. Future blueprints should explore restart-with-summary (Config E) or selective compaction (keep recent N tools + all edits) instead of naive truncation.

4. **Turn budgets show diminishing returns**: 10→15 turns yields +12pp, 15→20 yields +4pp, 20→30 yields +8pp. The inflection point depends on the task distribution. For SWE-bench Lite, 15-20 turns is the sweet spot for iteration speed vs quality.

5. **Bare-metal eval limitations**: Without Docker, only ~50% of SWE-bench repos can be tested (Django, pytest, sympy work; others have dependency conflicts). Future blueprints targeting full SWE-bench evaluation should budget time for Docker setup or accept pass rate as a lower bound.

6. **vLLM Mistral parser bug (#23180)** blocks multi-turn tool-use evaluation for external harnesses expecting OpenAI-spec tool_call IDs. This is already documented in tech-stack.md GPU Serving Conventions (line 135-137) but worth flagging for autoresearch blueprints that integrate external harnesses.

## Recommendations for autoresearch domain evolution

1. **Standardize harness adapter interface**: The `{WORKSPACE, ENDPOINT, MODEL, ISSUE_ID, PROBLEM_STATEMENT, TEST_CMD, REPO}` → `{"pass": bool, "turns": int, "tokens": int, "fix_generated": bool}` JSON output pattern works well. Codify this as the autoresearch harness adapter contract in project-structure.md.

2. **Extract harness ensemble orchestrator as reusable module**: The multi_harness_eval.py pattern of running N harnesses + taking union is general. Consider elevating to a shared autoresearch module for future blueprints.

3. **Document "Parkinson's Law for Agents" as a research finding**: This behavioral pattern (models delay edits to final third of budget regardless of budget size) is significant enough to warrant a standalone research note or blog post. It has implications for agentic prompt engineering beyond this blueprint.

4. **Add turn pressure patterns to agent scaffolding best practices**: The explicit "You MUST edit now" injection is a pragmatic workaround for model procrastination. While it feels like prompt engineering, it's load-bearing for 24B models. Consider whether this should be a recommended pattern for all agent loops or a signal that the model needs better task planning capabilities.
