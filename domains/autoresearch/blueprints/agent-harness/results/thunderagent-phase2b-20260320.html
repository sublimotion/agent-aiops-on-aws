Implementation Gap Analysis

MISSING True Preemption

The paper uses vLLM's sequence abort API to preempt backfill requests when the original program returns from tool execution. Our proxy only does admission control — it lets backfilled requests run to completion, pushing concurrent sequences above max_active=4. This causes memory pressure and likely explains the -18pp fix rate drop at N=8.

MISSING KV Cache Awareness

The paper tracks warm vs cold KV caches per program, prioritizing programs with resident cache. Our message-hash tracking creates new program IDs per issue (not per worker), losing cross-turn KV state. With proper tracking, returning programs would get faster TTFT from warm cache hits.

PARTIAL Program State Tracking

We correctly detect REASONING → ACTING transitions (inference complete) and ACTING → REASONING (new request). But OpenCode/Bun creates new TCP connections per request, breaking connection-based identity. We fall back to hashing the first user message — stable per issue but not per worker session.

MATCH Bubble Detection

Our 49% tool time measurement matches the paper's 40-60% claim exactly. The GPU bubble problem is real: at any moment, roughly half the "active" agents are executing tools while GPUs hold idle KV cache. This is the fundamental opportunity ThunderAgent exploits.

MATCH Zero Queue Depth

Even at N=8 (2x oversubscribed), zero requests were ever queued. All 1136 requests were served immediately via direct admit (81.5%) or backfill admit (18.5%). This matches the paper's claim that scheduling eliminates request queuing latency.

NOVEL Large MoE Validation

The paper only tested 7B-32B dense models. We validate the approach works on a 397B MoE (Qwen3.5-A17B active params) with TP4 on consumer Blackwell GPUs. The compute-reclamation principle holds even for large sparse models — tool bubbles still waste GPU cycles regardless of model architecture.

Key Takeaways

1. Admission-only scheduling gets 63% of the benefit with 10% of the complexity

Our ~300-line proxy achieves 1.63x throughput improvement (low end of paper's 1.5-3.6x). The paper's full system includes preemption, KV offloading, and tool resource management — each adding complexity but also throughput.

2. Quality degrades without preemption

The -18pp fix rate drop is the key gap. Without preemption, backfill admits push vLLM beyond its configured concurrency limit, causing memory pressure and degraded generation quality. A production system MUST implement preemption to maintain quality.

3. The bubble opportunity is validated at scale

49% tool time, 18.5% backfill rate, zero queue depth — these metrics confirm the core ThunderAgent thesis holds for large MoE models on consumer hardware. The scheduling opportunity is real, and even a simplified implementation delivers meaningful speedup.
