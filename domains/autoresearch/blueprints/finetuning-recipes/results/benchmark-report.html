Analysis

Matches BERT-class Models with 1.67% Params Trained

Our macro F1 of 0.883 matches fully fine-tuned BERT-base (0.882) and DistilBERT (0.883) — models with 66-125M parameters trained end-to-end. We achieve this with only 10.1M trainable LoRA parameters on a 606M base model. This validates that LoRA on small generative models is competitive with full fine-tuning of encoder models for classification.

Outperforms Mistral-7B + LoRA

Qwen3-0.6B + LoRA (0.883) outperforms Mistral-7B + LoRA (0.880) despite being 12x smaller. This aligns with the "recitation curse" finding in arXiv:2512.17630: larger general-purpose LLMs don't automatically outperform smaller models on specialized classification tasks. Model architecture matters more than raw parameter count.

~5 Points Below SOTA — Path Forward

The gap to Qwen-1.8B + LoRA (0.932) and ensemble SOTA (0.937) is ~5 F1 points. Three paths to close it: (1) Switch to Qwen3-1.7B — the search never explored the larger base model. (2) Increase LoRA rank from 16 to 32-64 — also unexplored. (3) Tune learning rate and epochs — stuck at defaults across all 34 experiments due to the narrow mutation strategy.

Search Got Stuck — Only 2 of 13 Parameters Explored

The sample_config(n_changes=2) mutation function randomly selects which 2 parameters to change. Across 34 experiments, it only ever selected lora_alpha and optim. Learning rate, rank, epochs, batch size, scheduler, dropout, sequence length, and base model were never touched. The mutation probability per parameter is ~15% per experiment, so exploring all 13 requires ~90+ experiments. A better strategy: grid-search the top 3 parameters first.

Methodology

Autoresearch Loop

Each experiment follows: mutate config → git commit → train → evaluate → keep/revert. The sample_config(baseline, n_changes=2) function randomly selects 2 hyperparameters from the search space and mutates them from the current best config. If macro F1 improves, the change is kept and becomes the new baseline. If it regresses, git reset --hard HEAD~1 reverts to the previous state. Changes accumulate — each kept improvement becomes the foundation for subsequent experiments.

Framework: autoresearch-colab Sentiment Module

Built on the autoresearch-colab sentiment module which provides: config.py (search space + mutation), data.py (multi-format data loading + chat template formatting), evaluate.py (macro F1 metric). Training uses Unsloth's FastLanguageModel with LoRA via TRL's SFTTrainer.

Qwen3 Thinking Mode Fix

Qwen3 models wrap responses in <think>...</think> tags. The evaluation function takes the first line of output, which returns <think> instead of the label — causing 0% match rate on a well-trained model. Fix: Strip thinking tags with re.sub(r"<think>.*?</think>\s*", "", raw_output, flags=re.DOTALL) before label extraction. This is Qwen3-specific; other model families don't need this.

Evaluation Protocol

Metric: macro F1 on a 300-sample stratified validation subset (from 3,000 total val samples). Macro F1 averages F1 across all 6 classes equally, penalizing poor performance on rare classes (surprise: 3.6% of data). Inference is greedy (temperature=1.0, do_sample=False) with max 16 new tokens. The model's raw output is stripped of thinking tags, then matched against the 6 valid labels.

Meta-Insights

Random Mutation Hits Diminishing Returns Fast

The improvement curve flattened after experiment 2 (F1=0.8758). Subsequent 32 experiments yielded only +0.0072 total. The sample_config(n_changes=2) approach explores a narrow neighborhood — with 13 parameters, each has ~15% chance of being selected per experiment. A hybrid strategy (grid-search top params first, then random mutation for interactions) would be more efficient.

95% GPU Headroom Is Untapped

At ~5 GB of 96 GB, the model uses 5% of available GPU memory. Increasing batch size from 4 to 32+ would speed up training ~4x. Training the 1.7B model would use ~15 GB — still well within bounds. The RTX PRO 6000 Blackwell is dramatically overprovisioned for 0.6B model LoRA fine-tuning.

Direct Loop > Claude Code for Config Search

The first attempt via Claude Code --print mode spawned unnecessary vLLM processes and hit API formatting issues. Running autoresearch_train.py directly is simpler and more reliable when the loop is just config mutation + train + eval (no code editing needed). Claude Code is better suited for the pre-training recipe loop where the agent needs to modify source code.
