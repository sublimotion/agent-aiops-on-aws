Key Architecture Insight
Three independent layers: the Inference Operator (Path A only), the KV Cache Infrastructure (L2 daemon + shm + FSx, shared), and Dynamo KVBM (self-contained per-worker, uses FSx only). llm-d deeply integrates with the L2 daemon; Dynamo brings its own cache hierarchy and only touches FSx for disk-tier persistence.

KEY DIFFERENCE
LMCache uses an external daemon (L2 ai-toolkit) for cross-pod cache sharing via shared memory. KVBM is self-contained per worker — no daemon, no shm, each worker manages its own GPU→CPU→disk hierarchy. Cross-worker sharing uses NIXL (network) instead.
Three Paths on Same Cluster

Path A: Managed Operator

  • IEC CRD → Operator reconciles
  • Ingress: ALB (auto-provisioned)
  • Router: Intelligent Router (closed-source)
  • Cache: Operator auto-injects LMCache config → same L2/L3 infra
  • + 1-CRD deploy, lowest ops
  • + JumpStart catalog, KEDA autoscaling
  • − No P/D disaggregation
  • − No expert parallelism

Path B: llm-d (K8s-Native) VALIDATED

  • Helmfile + Gateway API + Istio
  • Ingress: NLB + Istio Gateway
  • Router: EPP (Envoy ext-proc, OSS)
  • Cache: Manual config → same L2/L3 infra
  • + P/D disaggregation + NIXL/EFA
  • + Pluggable scorers, full control
  • + Uses managed KV cache w/o operator
  • − Higher ops burden (3 Helm charts)

Path C: NVIDIA Dynamo VALIDATED

  • 4 raw manifests (no Helm)
  • Ingress: NLB direct (no Istio)
  • Discovery: etcd (self-deployed)
  • Cache: KVBM G1→G2→G3 (self-contained)
  • + Simplest setup (fewest deps)
  • + No L2 daemon dependency
  • + A10G sm_86 confirmed compatible
  • − KVBM needs full stack (not just vllm-runtime)
  • − 12.3 GB image → DiskPressure risk
  • − NGC entrypoint needs override

Empirical Corrections to Architecture Doc
ADOT Collector Not Auto-Installed
Doc claims ADOT collector runs on system nodes and scrapes any Prometheus endpoint. Not found on our inference cluster. vLLM /metrics exposed but no scraper configured. May require separate addon installation or AMP workspace setup.
EnableClusterInference Fails
Inference operator addon installs successfully, but EnableClusterInference goes Enabling → EnableFailed consistently. Non-blocking for llm-d. May be required for Path A managed endpoints.
Shared Memory Name Requires Config
LMCache defaults to shared_memory. ai-toolkit uses ai_toolkit_cache. Doc doesn't emphasize this mismatch. Must set via BOTH kv_connector_extra_config AND LMCACHE_CONFIG_FILE (adapter reads config.extra_config).
UID Mismatch on Shared Memory
ai-toolkit creates shm as uid 1000 with 0600. vLLM runs as uid 2000. Permission denied until chmod 666. Production needs unified UIDs or supplemental GID. Not mentioned in the architecture doc.
FSx Root Needs Directory Setup
HyperPod-provisioned FSx root is 755 root:root. vLLM (uid 2000) cannot write. Need privileged init to mkdir -p /mnt/fsx/kvcache && chmod 777. Operator path may handle this automatically; llm-d path is manual.
CRD Coexistence Confirmed
Gateway API CRDs (inference.networking.k8s.io) and IEC CRDs (inference.sagemaker.aws.amazon.com) coexist without conflicts. All three paths can run on the same cluster simultaneously.
Dynamo-Specific Findings (Path C)
NGC Entrypoint Incompatibility
vllm-runtime:1.0.1 uses /opt/nvidia/nvidia_entrypoint.sh which fails with bare --model args. Fix: explicit command: ["python3", "-m", "vllm.entrypoints.openai.api_server"] in pod spec.
KVBM Not Active in vllm-runtime
The image bundles standard vLLM 0.16.0. DYN_KVBM_* env vars are set but not consumed. KVBM requires the full Dynamo stack (Frontend + Router + Planner), not just the worker image.
12.3 GB Image Causes DiskPressure
g5.4xlarge has ~95 GB ephemeral. Dynamo (12.3 GB) + existing images triggered DiskPressure taint. Fix: scale down other workloads first, let kubelet GC reclaim.
A10G (sm_86 Ampere) Compatible
Despite NGC targeting L40S/H100/B200, the vLLM runtime works fine on A10G with FlashAttention backend. Qwen3-0.6B loads in 3.4s, chat completion <1s TTFT.
FSx Coexistence Confirmed
Separate PV (fsx-dynamo-pv) with different volumeHandle suffix. Dynamo uses /mnt/fsx/kv-cache/, llm-d uses /mnt/fsx/kvcache — no conflict.
etcd Health Check Gotcha
etcd v3.5.17 image doesn't include wget or curl. Use etcdctl endpoint health for health checks instead.
