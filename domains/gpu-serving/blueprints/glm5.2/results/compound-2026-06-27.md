## Elevated to steering

### `.claude/steering/benchmark-analysis.md`

**3 new sections added**:

1. **"Verify-before-crediting-a-lever"** (L7 origin) — before crediting a lever with a measured delta, verify the effective configuration (what actually ran) vs the explicit configuration (what you set). Model defaults / auto-resolution can silently enable features, making a nominally "added" flag a no-op. Rule: when a delta is suspiciously small (<3%, within plateau threshold) for a structural lever (e.g., precision change), check the engine logs for what actually ran. GLM-5.2 DSA on SGLang v0.5.13: `quantization=fp8` auto-resolves `kv_cache_dtype=fp8_e4m3` even if the flag is absent.

2. **"Benchmark client artifacts can fake server-side SLO failures"** (L8 origin) — before diagnosing a concurrency ceiling as a server limit, confirm the failure against server-side metrics. Client-side request failures (timeouts, connection errors, retries) can stem from harness bugs (connector limits, connection reuse, ephemeral port exhaustion) and present identically to a real serving limit. Rules: (1) one fresh client process PER concurrency point; (2) confirm failure class against server metrics (num_retracted_reqs, engine error logs, nvidia-smi) before calling it a serving limit; (3) for c≥256, use TCPConnector(limit=0) AND a distributed driver. The L8 failure nearly cost a wrong knee (c256 recorded as ceiling when true comfortable knee was c320).

3. **"SGLang metric names differ from Prometheus-scraped names"** (L5 origin) — SGLang emits Prometheus metrics with colons (e.g., `sglang:time_to_first_token_seconds_bucket`). Prometheus sanitizes `:` → `_` on ingestion, so the stored metric is `sglang_time_to_first_token_seconds_bucket`. A PromQL query using the colon form is invalid and silently returns empty. Rule: always use underscore, never colon. Other SGLang metric name differences: TPOT → `sglang_inter_token_latency_seconds_bucket`, KV usage → `sglang_token_usage`, cache hit → `sglang_cache_hit_rate`, no native success/error counter (derive from `sglang_http_responses_total{status_code=~"2.."}`). Fixed in `.claude/skills/benchmark-runner/scripts/bench-standard.py`. The P0 TTFT-null gate (which blocks any benchmark run if TTFT can't be measured) now uses the correct underscore names.
