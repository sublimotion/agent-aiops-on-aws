Key Insights

vLLM Dominates Under Load: 3.1x Peak Throughput

vLLM's batch scheduling + FLASHINFER_MLA provides dramatically better throughput scaling. At c=512: 10,437 vs 3,400 tok/s (3.1x). SGLang saturates around c=128 while vLLM continues scaling near-linearly. This makes vLLM the clear choice for production concurrent workloads.

vLLM TTFT: 2-3x Lower Across All Workloads

FLASHINFER_MLA + prefix caching delivers 22-54ms TTFT vs SGLang's 82-155ms. The killer feature: 103x TTFT improvement on cold-to-warm prefix cache hit (5,928ms to 57ms). This is transformative for RAG and multi-turn chat.

HiCache Improves Single-Stream SGLang by 58%

SGLang + HiCache (200GB host memory/rank) boosts single-stream TPS from 86 to 136 (+58%) and ITL from 10.6ms to 6.7ms (-37%). The host memory tier eliminates GPU KV eviction overhead. However, HiCache does NOT help under load — at high concurrency, it matches or slightly trails base SGLang.

SGLang Prefix Caching: No Benefit Observed

RadixAttention showed 1.0x improvement in W2 RAG tests — effectively no caching benefit. The benchmark's prefix patterns may not trigger RadixAttention's exact radix tree matching. In contrast, vLLM's prefix caching produced 103x improvement on the same workload.

SGLang Cold Start: 2.8x Faster

SGLang starts in 3 min vs vLLM's 8.3 min — critical for spot instances where preemption restarts are expected. For latency-tolerant batch workloads on spot, SGLang's faster recovery may outweigh vLLM's throughput advantage.

K2.6 vs K2.5: Generational Leap

B300 + vLLM v0.19 delivers 3.1x single-stream TPS (128 vs 41 tok/s), 25-71x lower TTFT (22-62ms vs 1,216-1,565ms), and ~500x lower cost per token vs K2.5 on H100. Combined hardware + software gains are transformative.
