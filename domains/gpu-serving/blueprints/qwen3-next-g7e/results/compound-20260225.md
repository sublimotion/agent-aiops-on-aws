## Key insights elevated

### 1. Capacity strategy for scarce GPU instances
The g7e capacity crisis revealed a systemic gap: when targeting newly-launched GPU instance types, the standard EKS managed node group + multi-AZ approach does not work. The elevated rule codifies the "shotgun launch across regions" pattern and documents that EC2 dry-run is useless for capacity validation (it only checks permissions/quotas, not physical availability). This applies to any future scarce GPU deployment (e.g., Trainium3, next-gen GPUs).

### 2. Bare EC2 runtime differences
When forced to pivot to bare EC2 with an EKS-optimized AMI (outside an EKS cluster), multiple container runtime surprises emerged: containerd service not running by default, nerdctl GPU flag syntax differences, incompatibility of `--rm` with `-d`. These are platform constraints that apply to any bare EC2 + containerd scenario, not specific to g7e or Qwen3-Next.

### 3. Speculative decoding interconnect dependency
The MTP performance degradation on PCIe GPUs (2-41% throughput loss) is a fundamental architectural constraint: speculative decoding requires fast inter-GPU communication to amortize the overhead. The lesson elevates this as a hardware selection rule: test MTP on target hardware, default to baseline for PCIe platforms, reserve MTP for NVLink. This applies to all PCIe-interconnected GPU instances (g7e, g6e, g5.48xlarge, etc.).

### 4. Mamba hybrid model constraints
Qwen3-Next exposed a model architecture pattern that affects caching and speculative decoding: hybrid attention+mamba models trigger experimental mamba cache mode in vLLM, which conflicts with MTP. The elevated rule tells deployers to verify model architecture before assuming transformer-only optimizations apply. This is a cross-cutting validation step for any MoE or hybrid model.

### 5. Terraform operational patterns
Three Terraform issues (project name length, state locks, state attribute mismatches) were elevated because they represent workflow failures that apply to any Terraform-managed infrastructure, not just GPU serving. These are preventable with upfront checks.
