# Stratified OCR test corpus

Six synthetic document images that span the doc-type axis we care about for
OCR benchmarking. All are generated by `generate_corpus.py` (PIL only, no
GPU, deterministic). No hotlinking; no licensing risk; fully reproducible.

Regenerate at any time:
```bash
python3 scripts/test-assets/generate_corpus.py
```

## Why stratified?

A single image (the 19 KB `sample-doc.png` we used in iterations 1-4) is
not representative of real OCR traffic. Across real documents, the two
model inputs vary by about **16×** (image tokens: ~300 for a receipt vs
~5000 for a dense newspaper page) and the outputs by about **100×** (40
tokens for a receipt vs 1500+ tokens for a dense page). Throughput and
latency quoted from a single-image benchmark are approximately meaningless
for capacity planning.

## Manifest

| File              | Doc type     | Dimensions | File size | Target image tokens | Target output tokens | Generation |
|-------------------|--------------|------------|-----------|---------------------|----------------------|------------|
| `receipt.png`     | receipt      | 400×600    | 26.6 KB   | 300–600             | 40–100               | 6-item line-item list with totals block |
| `article.png`     | article      | 1000×1400  | 76.7 KB   | 1200–2000           | 300–500              | Headline + byline + 3 body paragraphs |
| `table.png`       | table        | 1000×800   | 37.3 KB   | 2000–3000           | 500–900              | 5-row × 5-column grid with headers + footnote |
| `formula.png`     | formula      | 1000×800   | 58.2 KB   | 1500–2500           | 400–700              | Attention mechanics with 5 equations + prose |
| `dense.png`       | dense        | 1200×1600  | 116.1 KB  | 3000–5000           | 1000–1500            | 2-column newspaper layout, small body font |
| `handwritten.png` | handwritten  | 800×1000   | 93.7 KB   | 800–1500            | 200–400              | Lined paper, cursive/script-style font |

**Targets are approximate.** Actuals are recorded in the per-doc-type
artifact sections (`extensions.stratification.per_doc_type[]`) after each
run. The point of this corpus is *spread* across the input/output variance
axis, not hitting exact token counts.

## Generation notes

- All images are saved as PNG with `optimize=True, compress_level=9` to
  keep each under 200 KB.
- Handwriting uses a cross-platform font fallback chain: Bradley Hand,
  Chalkduster, Apple Chancery, Comic Sans, DejaVu Serif Italic — whichever
  resolves first.
- Body text uses Arial / DejaVu Sans where available; the intent is
  reproducibility across macOS dev boxes and Linux container runtimes, not
  a specific font identity.
- No external URLs, no copyrighted imagery, no hotlinking — all content
  is original synthetic data.

## Sample content bucket

- **Receipt** — coffee-shop tab: 6 line items, subtotal, tax, total, card
  auth line. Small/medium image, short output.
- **Article** — "Continuous Batching in Modern LLM Serving" op-ed:
  headline + byline + 3 paragraphs. Medium image, medium output.
- **Table** — "Q2 Server Benchmark Results — OCR Engines": 5×5 grid
  (Engine, Throughput, Latency p99, Cost per 1K req, Accuracy). Medium
  image, medium-long output (table structure inflates token count).
- **Formula** — "Attention Mechanics — Reference Sheet": 5 equations
  rendered as unicode math text (softmax attention, multi-head concat,
  FLOP count, FlashAttention memory bound) interleaved with prose.
- **Dense** — "The Daily GPU Gazette", 2-column newspaper front page with
  4 stories (Blackwell supply, L40S utilization, NCCL 2.28, agent harness
  consolidation). Large image, long output.
- **Handwritten** — personal letter on lined paper, 15 short lines.
  Medium image, short-to-medium output (vision encoder carries more image
  tokens than the text density would suggest because the script font is
  visually complex).

## Legacy asset

`sample-doc.png` (640×480, 19 KB) is kept in place for the existing
`run-chatbot-short.sh` smoke cell (c=1, 100 requests). All other runners
use this 6-doc corpus via `_common.load_corpus()`.
