# Driving Sub-$2/M Token Inference on AWS: From Blackwell Cost Advantage to Full-Stack Optimization

## Executive Summary

Customers running large language models on AWS today can already achieve **$1.06/M output tokens** on Blackwell g7e instances — **4.6x cheaper** than H200 on-demand and **2.4x cheaper** than production-optimized H200 deployments on capacity blocks — with zero sacrifice in per-GPU throughput. On H200, extended context benchmarks proved that even 126K–252K-context workloads are SLO-compliant when batching and prefix caching are applied correctly. The constraint on cost-optimized g7e (96 GB VRAM) is not memory but compute: our KV offloading tests showed that CPU swap-space has zero effect on high-concurrency performance because the bottleneck is prefill compute queuing — 5M tokens of prefill takes ~143 seconds regardless of available cache capacity. Meanwhile, multi-node FSx sharing was validated as effective for a specific set of production use cases: enterprises running shared system prompts across tenants (1.32x warm TTFT improvement), RAG workloads with frequently retrieved document chunks, cold-start recovery after replica restarts, and multi-turn conversations where each turn reuses KV from prior context. Two AWS capabilities turn these findings into managed, production-grade optimizations. **ALB Target Optimizer** deploys a sidecar agent on each replica that enforces strict per-target concurrency limits — signaling the load balancer only when a GPU is genuinely ready — preventing the prefill queue buildup that drove TTFT to 229 seconds under overload and keeping each replica in the concurrency sweet spot where batching delivers its full benefit. **FSx for Lustre as a shared KV cache tier** via GPU Direct Storage over EFA addresses the validated multi-node use cases: persisting prefix caches across restarts, sharing computed KV across replicas for multi-tenant workloads, and keeping long-lived session context warm — use cases where our benchmarks showed clear value, as opposed to single-node memory expansion where the overhead caused thrashing. Together, these let customers stay on cost-efficient Blackwell hardware for a broader range of production workloads, sustaining sub-$2/M token economics.

## Technical Detail

Benchmarking three GPU serving blueprints on AWS — Kimi K2.5 (1T MoE on p5e/H200), Qwen3-Next (80B MoE on p5en/H200), and Qwen3-Next on g7e (Blackwell RTX PRO 6000) — surfaced three key insights. First, **instance selection dominates cost-per-token**: Blackwell g7e matched H200 per-GPU throughput at 3.8x lower cost per GPU-hour ($2.07 vs $7.91/GPU/hr), driving output token cost to $1.06/M at QPS 8 versus $4.88/M for a single H200 replica on-demand, or $2.54/M for the recommended production config of dual TP=4 replicas on capacity blocks. Second, **parallelism strategy matters more than GPU count**: TP=4 consistently beat DP+EP by delivering 5.5x lower TTFT and 9% higher throughput on half the GPUs, and running two TP=4 replicas on a single 8-GPU p5en node doubled serving capacity without added infrastructure. Third, **batch utilization is a hidden multiplier that scales with context length**: at QPS 2.0, prefill amortization compressed 126K-context TTFT from 1,201ms to 261ms (4.6x), and 252K-context inference achieved 860ms TTFT with prefix caching — both on H200 without CPU offloading, leveraging 104.5 GiB of KV cache per GPU at 0.92 utilization. On g7e, context scaling was validated to 32K (TTFT 745ms at 24K input), and a dedicated KV offloading study revealed the real bottleneck: at 500 concurrent requests (5M tokens exceeding 2.76M KV capacity), increasing CPU swap from 4 GiB to 64 GiB had **zero effect** on throughput or latency — the constraint is prefill compute queuing (~143s), not KV overflow. GDS compat mode on EC2 NVMe likewise showed no benefit over CPU-mediated I/O (5.08 vs 5.31 GiB/s read). This means the solution for high-concurrency long-context on g7e is more prefill compute (disaggregated prefill/decode or more GPUs), not more memory. Additional findings: MTP speculative decoding degrades throughput by 2–41% on g7e's PCIe interconnect (NVLink required for positive ROI), prefix caching on H200 reduced 32K TTFT by 58% (372ms → 155ms), and FP8 at TP=8 is blocked on both vLLM and SGLang due to MoE block_k=128 incompatibility. Separately, our LMCache use-case benchmarks identified where FSx-backed KV sharing *does* deliver value: multi-node deployments with shared system prompts showed 1.32x warm TTFT improvement (111ms median across 2 replicas with FSx Lustre), and multi-turn conversations achieved 90–95% cache hit rates by turn 10–20. Conversely, single-node deployments with high tenant diversity saw LMCache *degrade* performance — 50 unique system prompts caused FSx I/O thrashing with 84x worse TTFT than baseline. **Two AWS capabilities close the remaining gaps along distinct axes.** *ALB Target Optimizer* deploys a sidecar agent on each inference target that enforces ground-truth concurrency limits — the agent signals the ALB only when the GPU is ready for the next request. This directly addresses the prefill compute bottleneck: by capping per-target concurrency at the level where batching is effective (QPS 4–8 sweet spot), it prevents the runaway queue that caused 229s TTFT under 1000-concurrent overload, turning optimal batch sizing from a lucky scheduling outcome into an enforced SLO guarantee. *FSx for Lustre as a shared KV cache tier* — leveraging true GPU Direct Storage over EFA — addresses the validated multi-node use cases: sharing computed KV across replicas (so instance 2 retrieves from FSx instead of recomputing a 4K system prompt), persisting prefix caches across restarts for cold-start recovery, and keeping multi-turn conversation context warm across sessions. The key architectural insight is that FSx value scales with `prefix reuse × instance count` — it is a multi-node coordination layer, not a single-node memory extender. Together, these two capabilities create a defensible path to sustaining **sub-$2/M output token economics** on cost-optimized Blackwell infrastructure across both compute-bound (high-concurrency prefill) and memory-bound (multi-node prefix sharing) production workloads.
