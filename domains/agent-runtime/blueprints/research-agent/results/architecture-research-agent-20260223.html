v27: NDJSON Streaming + Hard Pipeline Timeout

Research queries take 10-15 minutes. MCP clients time out at ~2 minutes. The fix (v26): /invocations returns a StreamingResponse(media_type="application/x-ndjson") that yields {"type":"progress"} keep-alive lines every 30 s while the pipeline runs, followed by the final MCP result as the last line. mcp-proxy.py converts progress lines to notifications/progress JSON-RPC notifications so Claude Desktop shows a live progress indicator. v27 adds a hard 25-minute pipeline ceiling (MAX_PIPELINE_SECONDS=1500) and a 30-minute wall-clock cap in the proxy (MAX_JOB_SECONDS=1800) to prevent infinite hangs from rate-limited sub-agents (Lesson #19).

Request Flow (v27)

1
User invokes research tool — types a query in Claude Desktop. The MCP client sends a tools/call JSON-RPC message with a progressToken in _meta.
2
mcp-proxy.py (local) — handles initialize, tools/list, ping instantly. For tools/call: calls invoke_agent_runtime with accept: application/x-ndjson.
3
AgentCore Runtime streams NDJSON — POST /invocations returns a StreamingResponse. The first byte arrives immediately (pipeline starting line), keeping the connection alive.
4
Progress ticks every 30 s — _stream_tools_call() runs run_query() as an asyncio.Task. While it runs, the generator yields {"type":"progress","label":"Research in progress..."} every 30 s.
5
mcp-proxy converts to notifications/progress — each progress NDJSON line is converted to a JSON-RPC notifications/progress notification written to stdout. Claude Desktop shows a spinner/progress indicator.
6
S3 upload + final result — after the pipeline completes, _stream_tools_call() yields an upload progress tick, performs _upload_outputs_to_s3(), then yields the complete MCP result JSON as the last NDJSON line.
7
mcp-proxy returns final result — the last NDJSON line (containing "jsonrpc":"2.0") is returned as the handle() return value and written to stdout as the tools/call response.

Key Lessons (AgentCore Runtime)

  • #7
    HTTP protocol contract: POST /invocations + GET /ping on port 8080. Wrong endpoints → 404.
  • #8
    Claude Code 2.x Bedrock env var: use CLAUDE_CODE_USE_BEDROCK=1, not ANTHROPIC_BEDROCK=1. Inject frozen boto3 credentials explicitly.
  • #9
    Non-root Dockerfile required: claude binary refuses --dangerously-skip-permissions as root. Add USER agent.
  • #10
    Endpoint version pinning: after update-agent-runtime, always call update-agent-runtime-endpoint --agent-runtime-version N separately.
  • #13
    No EFS support: files are ephemeral in AgentCore Runtime. Upload /app/files/* to S3 from server.py after each invocation.
  • #14
    Disable boto3 retries: set max_attempts=1 + read_timeout=1200. Default retries × timeout = deadlock.
  • #16
    NDJSON streaming for long tools/call: return StreamingResponse(application/x-ndjson) and yield progress bytes every ≤30 s. MCP proxy converts to notifications/progress. Without this, Claude Desktop times out at ~2 min.
  • #17
    Build instance must be in public VPC: blueprint VPC is private-only (no NAT). Use default VPC + public subnet for build EC2. Transfer context via S3 + SSM.
  • #18
    update-agent-runtime requires --role-arn: even for image-only updates, the role ARN must be passed explicitly. Unlike most AWS update APIs, this is not optional.
  • #19
    Hard timeouts for streaming pipelines: read_timeout resets every byte received. Add explicit wall-clock deadlines: MAX_PIPELINE_SECONDS=1500 in server.py, MAX_JOB_SECONDS=1800 in proxy. Prevents infinite hangs from rate-limited sub-agents.
