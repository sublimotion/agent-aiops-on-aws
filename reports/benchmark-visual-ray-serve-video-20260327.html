Key Findings

Single-cluster in-memory is 1.57x faster at E2E p50. The S3 round-trip between PT and TF adds 111ms per frame — this overhead is eliminated entirely by using DeploymentHandle within one RayService cluster.
S3 passthrough doesn't scale to real-time video. At 30 fps, the S3 overhead alone (3.3s/s) exceeds the processing budget. With 10+ cameras, S3 PUT throttling (3,500 req/s) becomes a hard ceiling.
PT + TF coexist on GPU via runtime_env isolation. Each deployment gets its own virtualenv — torch and tensorflow don't conflict. Key dependencies: pin protobuf<5 and install nvidia-cudnn-cu12==9.3.0.75 for TF GPU on Ray's CUDA 12.5 image.
Dedicated KafkaIngress avoids GPU waste. The CPU-only ingress deployment decouples Kafka consumer scaling from GPU model scaling. No GPU cycles wasted on polling.
