Key Findings

Prefix caching: 82% TTFT reduction

With 1000 concurrent requests sharing an 8K system prompt, TTFT P50 drops from 77s to 13.5s. Throughput jumps +77% (40K to 71K tok/s). Under memory constraints, the impact is even larger: 94% TTFT reduction.

Concurrency is the primary latency driver

At 0.5 qps (14 concurrent), TTFT P50 = 238ms. At 5 qps (186 concurrent), TTFT P50 = 243ms. The customer's 940ms is caused by 1000 simultaneous requests, not config issues.

Customer config wins on random data

With random data at extreme concurrency, customer flags (no prefix caching, no chunked prefill) produce 49,558 tok/s vs 40,319 tok/s for our optimized config. No cache lookups on cache-miss data = less overhead.

KV offloading blocked on hybrid attention

All 4 offloading approaches (cpu-offload-gb, Dynamo KVBM, OffloadingConnector, LMCacheMPConnector) fail. Qwen3-Next's hybrid attention requires HMA, which vLLM 0.16 KV connectors don't support.

Blocked Tests: KV Cache Offloading

All 4 KV offloading approaches failed with Qwen3-Next on vLLM 0.16.0 due to hybrid attention architecture.

Approach Error Root Cause
--cpu-offload-gb (T5b) Cannot copy out of meta tensor V1 engine uses meta tensors for FP8, incompatible with CPU offload
Dynamo KVBM (T5d) dynamo-run: not found Dynamo 0.9.0 removed CLI; new distributed API incompatible with vLLM 0.16
OffloadingConnector (T5d) Hybrid KV cache manager disabled KV connectors auto-disable HMA; Qwen3-Next requires HMA for hybrid attention
LMCacheMPConnector (T5d) Hybrid KV cache manager disabled Same HMA incompatibility as OffloadingConnector
Workaround: For memory-constrained scenarios, prefix caching (T5c) delivers 94% TTFT reduction without any offloading. KV connector HMA support is expected in a future vLLM release.

Recommendations for Customer

Prioritized action items based on benchmark results.

1. Enable prefix caching

Add --enable-prefix-caching. If workload has shared system prompts, this delivers 82% TTFT reduction and 77% throughput increase.

2. Enable chunked prefill

Remove --no-enable-chunked-prefill. Improves scheduling fairness at high concurrency, prevents head-of-line blocking.

3. Rate-limit requests

Cap at 200-500 concurrent requests. At 5 qps (~186 conc), TTFT P50 = 243ms. The 1000-concurrent burst is the root cause of high latency.

4. Deploy 2x TP=4 replicas

Two replicas on p5en.48xlarge deliver 84,628 tok/s (1.71x). Zero failures at 1500 concurrent. Recommended production topology.

5. Consider TP=8 for extreme load

Using all 8 GPUs doubles KV cache capacity and prefill throughput for single-replica scenarios.

6. Evaluate MTP trade-offs

MTP adds complexity and may not help at high concurrency where the bottleneck is prefill, not decode. Not testable on stable vLLM for Qwen3-Next.
