Bitter Lesson Validation

Does raw scale beat finetuning?

Scale wins on SERA: Devstral 24B (46%) → Qwen3.5 397B (72%) = +26pp. Bigger model, bigger fixes.
Scale ties on OpenCode: Devstral 24B (88%) = Qwen3.5 397B (88%). With the right harness, the small model matches the frontier.
SWE-bench finetuning hurts: Qwen 2.5 base (48%) → SWE-LM (18%) = -30pp. Task-specific finetuning narrowed capabilities.
Harness > model for weak models: Devstral has 50pp spread (38-88%) across harnesses. Choosing the right harness is as impactful as 16x scale.

Key Takeaways

1. OpenCode is the dominant harness. 88% fix rate for both compatible models. Its built-in tool set (glob, read, edit, bash, grep, write) + Vercel AI SDK produces the most fixes.
2. 2-harness union hits 96%. Qwen3.5 with SERA+OpenCode fixes 48/50 issues. Diminishing returns beyond 2 well-chosen harnesses for a strong model.
3. SWE-bench finetuning backfires. SWE-agent-LM is -30pp worse than its base model. Task-specific finetuning on narrow benchmarks destroys general coding ability.
4. Tool calling format is the #1 blocker. Qwen 2.5's bare JSON output prevents using OpenCode/Claude Code. Only SERA's regex fallback works. This artificial constraint dominates the results.
5. Scale helps SERA but not OpenCode. +26pp from Devstral→Qwen3.5 on SERA, but both score 88% on OpenCode. The harness can compensate for model weakness.
6. Models are highly complementary. 4-model SERA union (92%) far exceeds best single model (72%). Only 1/50 issues is fixed by all models. Ensemble strategy is promising.
